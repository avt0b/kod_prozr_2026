# Синтетические данные

Генератор и готовый набор для стенда. Модель сущностей — [contracts.md](../docs/contracts.md),
кейсы и объёмы — [data.md](../docs/data.md). Все лица вымышлены.

```bash
python3 -m data.generator --seed 42 --out data/generated/   # ~1 с, без внешних зависимостей
python3 -m data.generator.check                           # make data-check
python3 -m data.generator.check data/generated/sample --partial
python3 -m unittest discover -s data/tests -t .
```

| Путь | Что |
| --- | --- |
| `generator/vocab.py` | Справочники: ФИО, улицы, ОКПД2, штат органов и полномочия |
| `generator/world.py` | Примитивы: люди, компании, роли, контракты с уникальными контактами и реквизитами |
| `generator/cases.py` | Сценарий: штат, фоновые закупки, демо-кейсы H1, C2–C6, N1, доп. кейсы и шум |
| `generator/appeals.py` | 106 обращений из шаблонов фактов и стилей, демо-обращение H1 |
| `generator/check.py` | Проверки data.md §7 |
| `generated/` | Полный набор, `_truth/` (разметка) и `sample/` (связная выборка) |

Набор хранится в git: генерация детерминирована, но предрасчёт анализа обращений (AI-06)
зависит от LLM. Загрузка: `cd backend && uv run python -m src.seed --dir ../data/generated`
(в Docker каталог монтируется в `/app/data`).

## Разметка `_truth/`

- `schemes.json` — `[{case_id, rule_codes, person_id, evidence_ids, note}]`. Шум — `rule_codes: []`.
  Ключи кейсов: `H1`, `C2`…`C6`, `N1`, `X1`/`X2` (конкуренты H1 в рейтинге), `R01-*`…`R08-*`,
  `N-*` (ложноположительные).
- `appeals_labels.json` — категория, `is_corruption`, ожидаемая привязка, кандидаты без
  автопривязки, сигналы, стиль, prompt injection, `keep_new` (демо-обращение H1 не разбирается заранее).
- `peer_anomalies.json` — служащие с заложенными аномалиями R08 и их признаки.
- `meta.json` — seed, порог и id служащих по кейсам.

## Как заложены схемы

- Рейтинг до демо: X1 и X2 по 80, Соколов (H1) — 74, 3-е место. Демо-обращение поднимает R07
  H1 до `medium` (≥ 87) и выводит его на 1-е место, если анализ считает конкретность по ai.md §2.
- R06: каждая группа ОКПД2 закреплена за одним служащим с полномочием `procurement`, поставщиков
  в группе 7–12, поэтому доля одного поставщика выше 50 % только в заложенных кейсах.
- R05: телефоны и адреса уникальны после нормализации (как в `risk/domain/contacts.py`), кроме
  заложенных совпадений и двух адресов массовой регистрации (12 и 9 компаний).
- R03/R04: прошлая и последующая работа обычных служащих — только у компаний без контрактов.
- Тексты обращений генерируются шаблонами без LLM (офлайн и воспроизводимо); метки берутся из шаблона.
