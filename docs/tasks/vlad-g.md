# Влад Гуселетов — фронтенд: каркас, рейтинг, профиль, докладная

Общий порядок: [workflow.md](../workflow.md). Перед реализацией — GitHub issue,
метка зоны и assignee; ветка от `dev`, рабочий PR в `dev`.
Для разделения работы между людьми — [/task-handoff](../../.agents/skills/task-handoff/SKILL.md).

Ты отвечаешь за основу фронта (каркас, API-клиент, моки) и экраны вокруг служащего: главную, рейтинг, профиль, докладную. Граф и обращения делает Егор, ему нужны твои типы и клиент как можно раньше.

Читать перед стартом: [contracts.md](../contracts.md), [frontend.md](../frontend.md), [demo.md](../demo.md) (что увидит жюри).

---

### F-01. Каркас, роутинг, layout
**КТ:** КТ0 · **Зависит от:** —

- React + TypeScript + Vite, Mantine, React Router, TanStack Query ([frontend.md §1](../frontend.md)).
- Маршруты: `/`, `/officials`, `/officials/:id`, `/appeals`, `/appeals/new`, `/appeals/:id`, `/reports/:id`, `/assistant`.
- Layout с боковым меню, тема, страница 404.
- ESLint и Prettier, Dockerfile (nginx, порт 80, SPA-фоллбэк, build-arg `VITE_API_URL`).

Готово, когда:
- [ ] `npm run build` и `npm run lint` проходят;
- [ ] Егор может добавлять свои страницы, не трогая роутер больше чем одной строкой.

---

### F-02. Типы по контракту, API-клиент, моки
**КТ:** КТ0 · **Зависит от:** T-01

- Типы всех сущностей и ответов из [contracts.md](../contracts.md), после созвона T-01 без пометок «ДОДУМАНО».
- Клиент с базовым URL из `VITE_API_URL`, разбор ошибок API в одном месте.
- Моки по флагу `VITE_USE_MOCKS=true` с демо-кейсами H1, C2–C6, N1 из [data.md §4](../data.md) (те же ФИО и компании) и 6–8 обращениями.

Готово, когда:
- [ ] переключение моки ↔ реальный бэк — только переменной окружения;
- [ ] Егор берёт типы `Graph*` и `Appeal*` из `shared/api`.

---

### F-03. Главная: счётчики и топ-10
**КТ:** КТ1 · **Зависит от:** F-02

- Карточки из `/stats/overview`: служащие с флагами, флаги по уровням, обращения по статусам.
- Топ-10 служащих по риску со ссылкой на профиль.
- Кнопка «Пересчитать риск» (`POST /risk/recompute`).

Готово, когда:
- [ ] на моках H1 стоит в топе, клик открывает профиль.

---

### F-04. Рейтинг служащих
**КТ:** КТ1 · **Зависит от:** F-02

- Таблица: ФИО, должность, орган, балл риска (цветной бейдж), бейджи флагов.
- Поиск по ФИО с задержкой ввода, фильтр по органу и минимальному баллу, сортировка, пагинация.
- Фильтры хранятся в URL, чтобы ссылкой можно было поделиться.

Готово, когда:
- [ ] все фильтры работают на моках и дают запросы по контракту.

---

### F-05. Профиль: сведения
**КТ:** КТ1 · **Зависит от:** F-02

- Шапка: ФИО, текущая должность и орган, балл риска.
- Блоки: история должностей, полномочия (вид и сфера), родственники, компании (свои и через родственников, с числом и суммой контрактов).
- Место под граф Егора (компонент `RelationGraph`).

Готово, когда:
- [ ] профиль H1 на моках показывает супругу и ООО «ДорСтройРесурс» с 5 контрактами.

---

### F-06. Профиль: флаги риска
**КТ:** КТ2 · **Зависит от:** F-05

- Список флагов: код и название правила, уровень, объяснение, норма права (`legal_ref`).
- Выбор флага передаёт его `evidence` в граф, где Егор подсвечивает цепочку.

Готово, когда:
- [ ] клик по R01 у H1 подсвечивает в графе цепочку служащий → супруга → ООО → контракты.

---

### F-07. Переход на реальный API
**КТ:** КТ2 · **Зависит от:** B-05, B-06, B-10

- Отключить моки, пройти все свои экраны на реальном бэке.
- Состояния загрузки, пустые списки, ошибки — на каждом запросе.
- Расхождения с контрактом — сразу Роману или Мише и в [contracts.md](../contracts.md), не чинить в моках.

Готово, когда:
- [ ] главная, рейтинг и профиль работают с `make up && make seed` без моков.

---

### F-08. Экран докладной
**КТ:** КТ3 · **Зависит от:** B-16

- Кнопка «Сформировать докладную» в профиле → `POST /reports` → переход на `/reports/:id`.
- Просмотр текста в виде документа, кнопка «Копировать».

Готово, когда:
- [ ] докладная по H1 открывается из профиля за один клик.

### F-09. Полировка интерфейса

Готово, когда:
- [ ] сценарий демо проходит без визуальных огрехов на 1920×1080.
