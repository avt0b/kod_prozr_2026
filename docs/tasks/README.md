## Как работаем

- **ID задачи** — префикс зоны и номер: `T` — общие, `B` — бэк, `F` — фронт, `AI` — ИИ и данные, `OPS` — DevOps.
- **Регламент:** [workflow.md](../workflow.md) и [AGENTS.md](../../AGENTS.md). Сначала полный GitHub issue с assignee и меткой зоны; номера `B-05` и т. п. — ID плана, а не номера issues.
- **Ветка:** от `origin/dev`, `<feat|bug|fix>/<area>-<issue>-<slug>`, например `feat/tskbcknd-123-officials-list`. Рабочий **PR в `dev`**, релизный — `dev → main`. Ревью от своей зоны, для контракта — от потребителя.
- **Несколько исполнителей:** [/task-handoff](../../.agents/skills/task-handoff/SKILL.md) сначала уточняет число людей, затем готовит issues и отдельные MD с владельцами файлов и порядком интеграции.
- **Сообщения коммитов/PR:** только задача, изменения и проверки, без служебных подписей об инструментах разработки; см. [правила](../workflow.md#6-сообщения-коммитов-и-pr).
- **Статус** меняет исполнитель прямо в таблице ниже: `todo` → `wip` → `review` → `done`. Если застрял больше чем на час — пишет в общий чат, а не сидит молча.
- **Контракт** — [contracts.md](../contracts.md). Кто меняет API или модель, тот правит контракт в том же PR.
- **Приоритет:** сначала всё, что входит в MVP (раздел «MVP» в [plan.md](../plan.md)). Задачи с пометкой «если успеваем» не берём, пока MVP не зелёный.
