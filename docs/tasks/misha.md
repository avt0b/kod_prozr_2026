### B-03. Загрузчик сидов `make seed`
**КТ:** КТ1 · **Зависит от:** B-02, AI-01 · **Ссылки:** [data.md §3](../data.md)

- Точка входа `python -m src.seed <путь>`: читает JSON-файлы по сущностям из `data/generated/` (или `sample/`) и пишет в БД в правильном порядке.
- Перед загрузкой очищает таблицы, повторный запуск даёт тот же результат.
- `_truth/` не загружать в доменные таблицы, это эталон для оценки.
- После загрузки вызывает пересчёт риска (когда появится B-10).

Готово, когда:
- [x] полный объём (~150 служащих, ~2000 контрактов, ~100 обращений) грузится меньше чем за минуту;
- [x] ошибки формата показывают файл и запись.

### B-11. `GET /officials/{id}/graph`
**КТ:** КТ2 · **Зависит от:** B-03 · **Ссылки:** ADR-03, [plan.md — риски](../plan.md)

- Обход от служащего на глубину `depth` (по умолчанию 2): должности → органы, родственники, компании (роли), контракты, обращения с упоминанием.
- Ответ `{nodes: [{id, type, label, risk?}], edges: [{source, target, type, label}]}`, типы рёбер по контракту.
- Контракты одной пары «компания — орган» сворачивать в один узел «N контрактов на X ₽», иначе граф нечитаем.
- Лимит узлов (стартово 150), при превышении — флаг `truncated` в ответе.
- id узлов совпадают с `node_id` в `RiskFlag.evidence`.

Готово, когда:
- [x] граф H1 показывает цепочку Соколов → супруга → ООО «ДорСтройРесурс» → контракты → орган O1;
- [x] ответ на любом служащем быстрее 300 мс на сидах.

### B-12. LLM-порт
**КТ:** КТ2 · **Зависит от:** B-01 · **Ссылки:** ADR-05, [ai.md §1](../ai.md)

- Интерфейс в `core`: `complete_json(system, user, schema) -> dict` и `complete_text(...)`.
- Адаптер к OpenAI-совместимому API (`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`), таймаут и одна повторная попытка.
- Фоллбэк-реализация без LLM, на которую переключаемся при ошибке или пустом `LLM_BASE_URL`.

Готово, когда:
- [x] при выключенной LLM всё работает на фоллбэке, в логах видно переключение;
- [x] Влад О. подключает свой `analyze_appeal` через этот порт, не трогая инфраструктуру.

### B-13. Модуль обращений: API
**КТ:** КТ2 · **Зависит от:** B-12

- `GET /appeals` (фильтры `status`, `category`, пагинация), `GET /appeals/{id}` с `linked_persons`.
- `POST /appeals {text, channel}`: создать, вызвать `analyze_appeal` и `match_persons` (функции Влада О., до их готовности — фоллбэк), сохранить `analysis` и `linked_person_ids`, статус `analyzed`.

- `analysis = null`, пока статус `new`.

Готово, когда:

### B-16. Докладная: `POST /reports` и `GET /reports/{id}`
**КТ:** КТ3 · **Зависит от:** B-10 · **Ссылки:** [ai.md §5](../ai.md)

- Черновик по шаблону из фактов БД: сведения о служащем, должность и полномочия, выявленные флаги с объяснениями и нормами, связанные обращения, предлагаемые меры.
- Обязательный дисклеймер «Сформировано автоматически. Решение принимает уполномоченное лицо».
- Точка расширения под LLM-текст (AI-09), но шаблон работает без LLM.

Готово, когда:
- [x] докладная по H1 читается как служебный документ и содержит все флаги.
