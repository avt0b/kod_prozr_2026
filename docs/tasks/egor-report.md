## Воспроизведение на Windows (PowerShell)

Нужны Node.js 22.18+, Docker Desktop и uv. Команды выполняются из корня репозитория; процессы API/Vite запускайте в отдельных терминалах.

```powershell
# Отдельный тестовый Postgres. Не используйте производственную БД.
docker run -d --name kodprozr_egor_test_db -e POSTGRES_USER=kodprozr -e POSTGRES_PASSWORD=kodprozr -e POSTGRES_DB=kodprozr -p 127.0.0.1:15432:5432 postgres:16-alpine
cd frontend
npm ci
npx playwright install chromium
# Каталог должен отсутствовать; helper откажется перезаписывать существующий.
node --experimental-strip-types tests/export-real-fixture.mjs ../egor-test-fixture
cd ../backend
uv sync --frozen
$env:DATABASE_URL='postgresql+asyncpg://kodprozr:kodprozr@localhost:15432/kodprozr'
$env:CORS_ORIGINS='http://127.0.0.1:5174'
uv run alembic upgrade head
uv run python -m src.seed --dir ../egor-test-fixture
uv run uvicorn src.web.main:app --host 127.0.0.1 --port 8001
```

Во втором терминале:

```powershell
cd frontend
$env:VITE_USE_MOCKS='false'
$env:VITE_API_URL='http://127.0.0.1:8001/api/v1'
npm run dev -- --host 127.0.0.1 --port 5174 --strictPort
```

В третьем терминале:

```powershell
cd frontend
$env:TEST_BASE_URL='http://127.0.0.1:5174'
$env:TEST_API_URL='http://127.0.0.1:8001/api/v1'
# Необязательно: использовать установленный Edge вместо скачанного Chromium.
$env:TEST_BROWSER_CHANNEL='msedge'
npm run test:e2e
```

Для моков запустите Vite с `VITE_USE_MOCKS=true` на 5173 и уберите `TEST_API_URL`; `TEST_BASE_URL` задайте на 5173. Новые обращения моков существуют только до перезагрузки вкладки. Браузерные артефакты сохраняются в игнорируемом `frontend/test-results/`.

## Совместимость без изменения контракта

API не менялся. В `shared/api/officialAdapters.ts` добавлен адаптер к уже существующим DTO бэкенда:

- `evidence[].id` преобразуется в `node_id`; полные флаги получаются через `/officials/{id}/flags`, поскольку профиль отдаёт краткие флаги без evidence.
- `position` и `organ` рейтинга могут быть объектами; действующее назначение выводится раньше завершённого.
- Плоские связи компаний преобразуются для существующего интерфейса; отсутствующие число и сумма контрактов показываются как отсутствие данных, а не ноль.
- Обращения используют обязательные `linked_person_ids`; имя и актуальный риск запрашиваются через общий кеш профилей, без зависимости от дополнительных полей `linked_persons`.
- `graph.truncated` — необязательное фактическое поле бэкенда, показывается предупреждение.
- Поле `analysis.engine` контрактом не принято; интерфейс не приписывает анализ модели. Реальная проверка выполнена на `rules`, это явно указано на слайдах.

Сумма сгруппированных контрактов обозначена `≈`: API отдаёт округлённые суммы в подписях, не точные числовые значения. Если хотя бы одной суммы нет, группа не создаётся. Если evidence содержит только часть контрактов одной группы, они не сворачиваются: лишние доказательства не подсвечиваются. Для точного итога нужен согласованный числовой атрибут суммы в API.

## Что мешает закрыть полный demo.md

1. Фоллбэк бэкенда на точном тексте H1 возвращает `procurement`, а demo.md ожидает `conflict_of_interest`. Сопоставление с Соколовым, сущности, R07, граф и докладная при этом работают. Фронтенд показывает ответ сервера без подмены категории. Нужна доработка AI-04/B-12.
2. Реальная логика реализована у R01, R02 и R07; зарегистрированные R03–R06 и R08 пока возвращают пустые результаты из `stubs.py`. Для всех демонстрируемых в demo.md флагов нужны задачи Романа B-09/B-15 и остальные правила; фронтенд их отобразит по API.
3. В репозитории отсутствуют генератор полного датасета и `make eval`/`eval/report.json`. На слайде 7 нет выдуманных precision/recall; нужно получить отчёт AI-08 и заменить блок об отсутствии измерений.
4. F-16 требует совместного прогона с Владом Г., F-17 — выступления Романа с таймером. Автоматические тесты не заменяют эти критерии. Заметки докладчика рассчитаны примерно на 4 минуты, оставляя минуту запаса в пятиминутном сценарии.
