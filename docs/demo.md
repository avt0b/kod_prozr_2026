## Чек-лист прогона «с нуля»

### За день до защиты: железо и окружение

- [ ] Основной ноутбук: Docker с Compose v2.24+, `make`, `python3` (для smoke), `uv` (для `make eval`
      и `make precompute`, если они понадобятся). Свободное место на диске проверено (`df -h`).
- [ ] Ресурсы ([devops.md §5–6](devops.md#5-локальная-llm-ollama), [ai.md §8](ai.md#8-выбор-модели)):
      без LLM хватит 2 vCPU и 4 ГБ RAM. С `qwen2.5:7b-instruct` на CPU нужно от 4 vCPU и 12–16 ГБ RAM,
      модель весит около 4.7 ГБ. С NVIDIA GPU нужен nvidia-container-toolkit (около 5 ГБ VRAM для 7B в Q4),
      иначе Ollama молча работает на CPU. Для слабой машины есть `qwen2.5:3b-instruct` (около 2 ГБ).
- [ ] Резервный ноутбук с тем же коммитом. Офлайн-пакет: `make offline-bundle` на подготовленной машине,
      перенос, `make offline-load OFFLINE_DIR=<пакет>` на резервной, затем `make reset OFFLINE=1`
      (без сборки и без обращений к registry). Порядок и проверки — [devops.md §9](devops.md#9-резервный-ноутбук-без-сети-дамп-видео).
- [ ] Видео-бэкап полного сценария записан с чистого стенда (`make reset && make video`, сценарий
      Playwright из #23) и лежит на обоих ноутбуках и на флешке вместе с дампом (`make dump`).
- [ ] Экран 1920×1080, масштаб браузера 100 %, уведомления ОС и мессенджеров выключены, проверен выход
      на проектор (HDMI/USB-C). Тёмная или светлая тема — та же, что на скриншотах слайдов.
- [ ] Решение по LLM принято заранее (см. «LLM: включить или выключить»), и прогон сделан в выбранном режиме.

### За 30–60 минут: стенд

- [ ] Рабочее дерево чистое (`git status`), записан хеш коммита (`git rev-parse --short HEAD`).
- [ ] `.env` создан из `.env.example`, режим LLM в нём соответствует решению.
- [ ] `make reset`: тома снесены, стек поднят, миграции и сиды загружены. `make ps` — все сервисы `healthy`.
- [ ] `curl -fsS localhost:8000/health` отвечает `{"status":"ok"}`, фронт открывается на `http://localhost:3000`.
- [ ] `make smoke` зелёный (50 проверок). Smoke **отправляет демо-обращение** и поднимает Соколова на
      1-е место, поэтому после него снова `make reset`. Проверить стенд, не меняя данные, можно командой
      `python3 scripts/smoke.py --keep-demo`.
- [ ] Исходное состояние: Соколов в рейтинге **не на 1-м месте**
      (`curl -s 'localhost:8000/api/v1/officials?limit=5'`). Баллы (15.11, полный объём, фоллбэк без LLM,
      веса ADR-16): **73 (3-е место) → 88 (1-е, отрыв 8)**. Выше H1 до обращения — два кейса по 80
      (R01+R02 и R01+R03+R05), ниже — 60. Порядок фиксирует `backend/tests/e2e/risk/test_demo_ranking.py`.
- [ ] Дамп чистого состояния: `make dump` (#25). Восстановление `make restore` быстрее полного `make reset`.
- [ ] Открыты вкладки: главная, рейтинг, `/appeals/new`. Текст демо-обращения лежит в буфере обмена и в
      файле `demo/appeal_h1.txt`.
- [ ] Отдельной вкладкой открыт `http://localhost:8000/docs` (на случай вопроса о журнале: `GET /api/v1/audit`;
      в интерфейсе журнал пока не выведен).
- [ ] Видео-бэкап открыт на втором экране на первом кадре.

После каждой репетиции — `make reset` или `make restore`. Повторная отправка того же текста балл не поднимает:
R07 считает обращения с одинаковым кратким содержанием один раз, а Соколов уже первый.

### LLM: включить или выключить

Замер AI-03 ([ai.md §8](ai.md#8-выбор-модели), 15.11): `qwen2.5:7b-instruct` на GPU 8 ГБ разбирает обращение
за 2–5 с, `POST /appeals` с демо-обращением целиком — 5–6 с; первая загрузка модели ~1 мин. Стенд демо
с этой GPU в Docker не проверяли, поэтому решение по-прежнему принимаем по факту прогрева на стенде.

- **Включить.** `make llm-up` скачивает и прогревает модель. В `.env`: `LLM_BASE_URL=http://ollama:11434/v1`,
  `LLM_API_KEY=ollama`, `LLM_MODEL=qwen2.5:7b-instruct`, затем `make up`. Прогрев — запрос прямо в Ollama
  (пример в [devops.md §5](devops.md#5-локальная-llm-ollama)), а не через `POST /appeals`: так данные не меняются.
- **Выключить.** В `.env` оставить `LLM_BASE_URL=` пустым и выполнить `make up`. Разбор обращений идёт на
  правилах и словарях, докладная — по шаблону, ассистент разбирает типовые вопросы без модели.
- **Порог решения (допущение):** если прогретая модель отвечает на текст демо-обращения дольше 20 с,
  демо идём без LLM. Бэкенд ждёт ответа LLM до `LLM_TIMEOUT_SECONDS=90` и после таймаута без повтора
  уходит на фоллбэк (повтор только при 5xx/429 и обрыве установленного соединения). Фронт ждёт ответа на
  `POST /appeals` 150 с. Для живого показа 90 с слишком долго, автоматически на фоллбэк по 20 с система
  не переключится.
- С LLM на CPU медленнее работают и докладная (LLM переписывает шаблон), и ассистент. На репетиции
  замерить все три шага.
- Если LLM недоступна совсем (контейнер не поднят, отказ соединения), бэкенд сразу уходит на фоллбэк.
  В карточке обращения это видно по бейджу «Разбор: правила (фоллбэк)». Если файрвол молча отбрасывает
  пакеты (DROP), например при Ollama на хосте и бэке в Docker, отказа нет, и бэкенд уходит на фоллбэк
  через `LLM_CONNECT_TIMEOUT_SECONDS` (5 с). LLM включаем, только если `make llm-check` показывает модели
  ([devops.md §5](devops.md#5-локальная-llm-ollama)).

### Резервные действия

1. **Разбор не пришёл за 20 с.** Не ждать 90 с. Если LLM включена, Кирилл останавливает её:
   `docker compose --profile llm stop ollama`. По коду адаптера оборванное соединение даёт один повтор,
   повтор не может соединиться, и разбор уходит на фоллбэк за секунды. **Это не проверено вживую —
   проверить на репетиции.** Для LLM на хосте или на другой машине остановка Ollama тоже сработает:
   при отказе или DROP повторное соединение отваливается через `LLM_CONNECT_TIMEOUT_SECONDS` (5 с).
   Если ответа всё равно нет, Миша открывает сохранённое в сидах демо-обращение (единственное в статусе
   `new` в списке обращений; id — в `data/generated/_truth/meta.json`, поле `demo_appeal_ids`) и нажимает
   «Запустить анализ».
   Не помогло — видео с шага «Разбор обращения».
2. **Нет привязки к Соколову.** Показать кандидатов привязки в карточке («возможно: …»), сказать:
   «При неоднозначности система не привязывает автоматически, решает аналитик». Открыть профиль
   Соколова из рейтинга и продолжить.
3. **Соколов не поднялся на 1-е место.** Вероятно, обращение уже отправляли без `make reset`.
   Сказать «балл вырос за счёт обращений» и продолжить с профиля, показав флаг R07.
4. **Докладная долго формируется.** Ждём не больше 20 с, затем показываем слайд с готовой докладной.
5. **Стенд упал целиком.** Кирилл говорит «резерв», Егор запускает видео с текущего шага, Роман продолжает
   рассказ по видео. Резервный ноутбук поднимаем только между выступлениями, не во время демо.
6. **Нет сети в зале.** Стенд работает локально, интернет не нужен, если образы и модель скачаны заранее
   (офлайн-пакет). Перезапуск без сети: `make reset OFFLINE=1`. Обычный `make reset` сначала собирает
   образы и без сети может упасть.
